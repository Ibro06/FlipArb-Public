Data pipeline

Cheap checks first. Deeper analysis only when it matters.

The pipeline is staged to preserve API budget and reserve expensive enrichment for candidates that have a reasonable chance of becoming actionable opportunities.

01
Source discoveryNew listings, ending auctions, misspellings, category feeds, seller inventory, and refresh checks.
02
Cheap viability screenReject obvious accessories, listings without images, and weak price candidates before expensive calls.
03
Verification and enrichmentUse deterministic rules, OpenAI analysis, comparable sales, repair pricing, and device status.
04
Decision signalsCalculate projected profit, ROI, confidence, risk, liquidity, and freshness.
05
Classification and feedbackSurface the strongest opportunities and record query performance for the learning system.

Decision logic

FlipArb avoids using purchase price as the only signal. It combines market evidence and operational costs before deciding whether a listing should be surfaced.

Projected profit = expected resale
minus purchase price
minus inbound shipping
minus purchase tax
minus parts cost
minus resale handling cost

The public version summarizes the logic. The production implementation remains private.

Machine learning

Bayesian learning allocates attention to better queries.

Thompson Sampling treats search queries as competing choices. Stronger observed outcomes improve a query posterior and increase its chance of receiving future scanning budget.

Online learning loop

Query posterior = Beta(alpha, beta)

alpha = alpha + reward
beta = beta + 1 minus reward

Rewards are quality weighted. Alert ready opportunities receive more credit than weak review candidates. Daily decay reduces the influence of stale history.

The objective is useful opportunities per unit of API budget, not maximum listing volume.

API architecture

API efficiency

Cycle budgets, caching, duplicate state, source efficiency tracking, staged enrichment, and throttle monitoring reduce unnecessary calls and help the scanner operate within platform constraints.

The project uses official API workflows and does not claim formal certification by eBay.

Real world validation

The system influenced actual purchasing decisions.

A portfolio project is stronger when the output is tested against reality. FlipArb was used to identify listings that became real resale transactions.

1. Identify

The scanner surfaced listings that passed profitability, confidence, risk, and quality gates.

2. Purchase

Selected devices were purchased and shipped to me for inspection and repair when needed.

3. Resell

Devices were later resold, connecting analytical output to real marketplace outcomes.
